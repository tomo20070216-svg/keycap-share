# docs/safety.md — 安全ルール

**このファイルはAIが自分で書き換えてはいけません。** 変更が必要だと思ったら、人間に変更案を提示し、承認を得てから人間(または承認を得た上でAI)が編集します。

## 人間の承認が必要な操作(必ず止まって確認する)

汎用ルール(利用者からの指定):

- メールやDMの送信
- SNS(X含む)への投稿
- 購入や決済
- データの削除
- 本番環境への反映
- 権限の変更
- 顧客・利用者への連絡
- 法的な同意

このプロジェクト固有の追加ルール:

- `git push`(リモートリポジトリへの反映)
- Supabaseの本番データベースへのマイグレーション適用、テーブル削除・変更
- Vercelの本番デプロイ(プレビューデプロイはこの限りではないが、結果は報告する)
- 新しい依存ライブラリ(npmパッケージ等)の追加(理由の説明とセットで確認を取る。`plan.md` 7章)
- 有料プラン・課金が発生しうる設定変更
- `tasks.json` の `passes`(合格条件)の変更・削除
- `docs/safety.md` 自体の変更
- 現在の git リポジトリ構成の変更(ホームフォルダがリポジトリルートになっている問題の修正含む。詳細は `progress.md` の初回エントリ参照)

## 絶対に行ってはいけない操作

- APIキー・パスワード・Supabaseの秘密鍵などをコードやMarkdownファイルに直接書き込む、またはコミットする。
- `git push --force`、`git reset --hard`、`git clean -f` の実行。
- コミット・pushフックのスキップ(`--no-verify` 等)。
- `tasks.json` のタスクを黙って削除する、または合格条件を自分に都合よく書き換える。
- Orca echoの物理レイアウト(キー数・配置)を、確認が取れていないのに確定情報として扱う、またはコメントの「仮の値」表記を消す。
- テストやビルドが失敗しているのに、失敗を隠す・無視する・「動いているはず」として報告する。
- 人間の確認なしに、無関係なファイル(ホームフォルダ配下の個人ファイルなど)を `git add` してコミットする。

## 秘密情報の扱い

- 環境変数(`.env.local` など)で管理し、`.gitignore` に含める。
- ドキュメント(`docs/*.md`, `plan.md`, `tasks.json` など)には実際の値を書かない。プレースホルダ(例: `SUPABASE_URL=<値は.env.localを参照>`)のみ書く。

## エスカレーション方法

判断に迷う操作は、上記リストになくても「これは念のため確認した方がよいか」を人間に聞く。曖昧なときは実行せずに止まる方を選ぶ。
