# docs/mission.md — 何のために作るか

出典: `plan.md` 1章・2章・6章を要約したもの。矛盾があれば `plan.md` が正。

## 目的

分割キーボードのキー配列を投稿・閲覧し、X(旧Twitter)で共有しやすくするサイトを作る。

- 最初の対象機種は **Keychron Orca echo のみ**。他機種は後回し。
- 配列ファイルの書き出し・取り込み(Launcher/QMK/Vial/ZMKなどの形式)は後回し。
- 作者(利用者第一号)は分割キーボード初心者で、「なぜこの配置にしたか」を書き残すことが主目的。

## 譲れない方針(これを壊す変更は人間の承認が必須)

1. **X共有が軸。** 配列ごとに固有URLを持ち、Xに貼ると画像つきカードが出る。
2. **メタタグはサーバー側で出す。** Xのクローラーは JavaScript を実行しないため。
3. **キー図の描画部品は1つだけ。** 画面表示とOGP画像生成で共用する。
4. **データは機種に依存しない形で持つ。** 「物理レイアウト」と「配列(割り当て)」を分離する。割り当ては表示用の名前(文字列)で持ち、Launcher/QMKのキーコードに直接結びつけない。
5. **Orca echoの物理レイアウトは推測で確定させない。** 仮の値として1ファイルに隔離し、「仮の値」と明記する。
6. **不明点は質問する。** 推測で仕様を埋めない。

## 今は作らないもの(後回し)

- 配列ファイルの書き出し・取り込み
- Orca echo以外の機種対応
- 機種をまたぐ配列の変換

ただし、データ設計と描画部品は「後から対応できる形」にしておく(機種に依存させない)。

## 成功の基準(ざっくり)

- 実際にXに投稿したとき、キー配置図つきのカードが表示される。
- 投稿者が「なぜこの配置にしたか」を書ける。
- Orca echoの実機情報が判明したとき、`src/keyboards/orca-echo.ts` 相当のファイル1つを差し替えるだけで反映できる。
