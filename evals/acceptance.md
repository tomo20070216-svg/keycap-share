# evals/acceptance.md — 検品(合格判定)の基準と方法

**原則**: AI自身の「完成しました」という発言は合格理由にしない。必ず、下記の「確認方法」を実際に実行した結果(ログ・画像・URL・テスト結果)を `tasks.json` の `evidence` に記録し、それを見て評価役が判定する。

## 共通の検品ルール

- `evidence` には、実行したコマンドと、その出力(またはスクリーンショットのファイルパス)をセットで記録する。「テストが通りました」だけでは不可。
- 評価役は、可能な限り自分でも同じ確認方法を再実行してから合格判定する。
- 不合格の場合は `tasks.json` の `status` を `blocked` にし、不足している証拠・失敗内容を具体的に書く。

## フェーズ別の合格基準

### フェーズ0: 土台
- 確認方法: 公開URL(Vercel)にブラウザまたは `curl` でアクセスし、200が返り、空ページが表示されること。
- 証拠: `curl -I <URL>` の出力、またはスクリーンショット。

### フェーズ1: データ設計
- 確認方法: 仮のOrca echoデータを使い、配列(layout)を1件保存し、APIまたはDB経由で取得できること。
- 証拠: 保存・取得のリクエスト/レスポンスのログ、またはテストコードの実行結果(Vitest)。
- 追加確認: `src/keyboards/orca-echo.ts` 相当のファイルの先頭に「仮の値」コメントがあることをファイル内容で確認する。

### フェーズ2: キー図の描画
- 確認方法: 仮の配列データを渡し、全レイヤーが画面上にSVGで表示されること。左右分割が視覚的に分かること。
- 証拠: ブラウザのスクリーンショット(全レイヤー分)。

### フェーズ3: 閲覧ページ
- 確認方法: `/k/[id]` と `/k/[id]/[layer]` のURLを実際に開き、配列とレイヤーが表示されること。一覧・新着・タグ絞り込みが動くこと。
- 証拠: 各URLのスクリーンショットまたはHTML出力。

### フェーズ4: OGP画像と共有(最重要)
- 確認方法:
  1. 該当ページの `<head>` に `twitter:card`(`summary_large_image`)、`og:title`、`og:image` 等が出力されていることをHTMLソースで確認する。
  2. `ImageResponse` で生成された画像(1200×630程度)を実際に開き、キー配置図・タイトル・機種名・投稿者名が入っていることを確認する。
  3. 可能であれば実際にXへ投稿するか、Xのカード確認手段(公式のカードバリデーター等、利用可能なもの)でプレビューを確認する。実際の投稿は「人間の承認が必要な操作」(SNS投稿)にあたるため、投稿自体は人間が行う。
- 証拠: HTMLソースの該当箇所、生成されたOGP画像ファイル、プレビュー確認のスクリーンショット。

### フェーズ5: 投稿エディタ
- 確認方法: 新規作成フォームから、機種・タイトル・基本レイヤーの割り当て・説明文を入力し、共有URLが発行されるまでの一連の操作を実際に行う。
- 証拠: 操作の各画面のスクリーンショット、発行されたURL。

### フェーズ6: 認証と運用
- 確認方法: 自分のアカウント(または秘密キー)で作成した投稿は編集・削除でき、他人の投稿は編集・削除できないことを確認する。投稿数制限が機能することを確認する。
- 証拠: 2つの異なるアカウント/秘密キーでのテスト結果ログ。

## 実装前検証(フェーズ0着手前、`tasks.json` P0-2 等)

- 日本語OGP画像: 実際に日本語を含む画像を生成し、文字化け・フォント欠落がないことを画像で確認する。
- Xログイン: 確認した最新の条件をURLや文書の出典つきでまとめ、人間に採用可否を確認する(推測で決めない)。
- Vercel/Supabase無料枠: 確認した最新の上限を出典つきでまとめ、人間に許容可否を確認する。
