# P2-4 写真からOrca echoの座標を推定 (2026-09-28)

## 方法
1. 実機写真 `docs/keyboards/orca-echo-photo.png`(1050×652px)を拡大し、目盛りを付けて各キーの中心をピクセル単位で読み取った(`coords.py` の `px`)。
2. 通常のキーは「キーの間隔は全体で共通、列ごとに段のずれだけが違う」という規則に最小二乗法で当てはめ、読み取り誤差をならした。結果: 横の間隔 66.6px、縦の間隔 65.8px(ほぼ同じで、実物のキーが縦横同じ間隔で並んでいることと整合する)。
3. 横の間隔を1キー分として換算し、`src/keyboards/orca-echo.ts` の座標を置き換えた。
4. 親指キー(約18度)・ダイヤル(約22度)の傾き、トラックボール・スクロールパッドの位置と大きさは、拡大画像から読み取った値のまま。

## 結果
- `compare.png`: 上が写真、下が推定座標で描いたキー図(通常レイヤー)。
- `dev-keymap-desktop.png`: 確認ページ `/dev/keymap` の全体。
- `npm test` 36件成功(キー数・要素の位置関係のテストを含む)。

## 人間による実機確認(2026-09-29)
- 列ごとの段のずれ: 合っている。
- 親指キー・ダイヤルの位置と傾き: 大丈夫。
- トラックボールの大きさ: このままでよい。
- 指摘: 写真の配置のずれで右手が少し上に写っているので、左右の高さをそろえる → 右手の要素すべてを左右の差の平均(0.1キー分)だけ下げた(`coords.py` の最後の段落)。テスト「左右の対応する列の高さがそろっている」を追加。
- 追加情報: トラックボールに押し込み(クリック)はなく、上下左右の操作だけ → 操作の種類から `click` を削除。
- 修正後の比較画像: `compare.png`。人間による最終確認は未。確認が取れるまで「仮の値」表記と `isProvisional: true` は維持する。

## ダイヤル・トラックボール・スクロールパッドの文字の置き方(P2-3からの持ち越し)
- スクロールパッド: 中に上から ↑・タップ・↓。
- ダイヤル: 右外に「右回し」「左回し」を縦に並べる。OGP画像用のフォント(Noto Sans JP)には回転の矢印(↻↺)が無く、文字化けしたため、文字で表す。
- トラックボール: 円の上下左右の外側に、それぞれの操作を置く。
- 外側の文字の枠がどの要素とも重ならないことは、テスト(`keymap-render.test.ts`)で確認している。左右の間(ダイヤルとトラックボールの間)は約1.9キー分で、両方の文字が並ぶため枠の幅を詰めている。
- OGP画像での確認: `og-preview-device-labels.png`(一時的なルートで生成し、ルートは削除済み)。
